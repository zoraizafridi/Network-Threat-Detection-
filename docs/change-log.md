## Phase 1: flow telemetry

New package `pk.ooad.ntd.flows`:

- `FlowRecord` is an immutable snapshot of one connection: five tuple, directional byte counters,
  packet count, start and end, observation flags, label, plus `ended` to tell open from closed.
  Two fields are documented projections, not measurements: `srcPort` is derived from the tuple
  because `NetworkEvent` carries only a destination port, and `bytesIn` stays zero because the
  simulator emits one direction only.
- `FlowQuery` carries the filters and `matches(FlowRecord)`; it is a record, so the API and the tests
  build the same object.
- `FlowRecorder` implements `Consumer<NetworkEvent>` and is registered on the detection engine. It
  aggregates on the five tuple, closes a flow after `flow.idleTimeoutSeconds`, keeps closed records
  in a bounded ring, purges past `flow.retentionMinutes`, caps open flows, and refuses to grow without
  limit. Labels come from configurable payload rules with the event type as a weaker fallback.
- `DetectionEngine.addEventObserver` taps the raw event stream before the detectors. An observer that
  throws is logged once and never stops detection; a null observer is ignored.

API and client:

- `GET /api/flows` with `src`, `dst`, `port`, `from`, `to`, `limit`; malformed values answer 400, and
  the allowlist entry was added to `API_PATHS`. Read only, so every authenticated role may call it.
- New Flows page (`/portal/flows`) in the Monitoring group: stat strip, text, label and protocol
  filters, sortable columns, label tally, pause control. It polls while open instead of using SSE.
- `src/flows.ts` holds the filter, sort, summary and formatting logic so it is testable without a DOM.

Tests added:

- `FlowRecorderTest`: aggregation, idle split, expiry on query, ring eviction, retention purge, every
  query filter, labels, protocol classification, derived ports, disabled mode, concurrent writers,
  reset.
- `EventObserverTest`: an observer sees every event and a throwing observer cannot stop detection.
- `WebServerTest`: flows recorded while the simulator runs, filter validation, viewer read access.
- `tests/flows.test.ts` and `tests/flowsPage.test.tsx`: filtering, stable sorting, summary, formatting,
  and the page rendering, filtering, empty state and pause behaviour.

Results: Java 144 tests green. Web 51 tests in 14 files green. `tsc --noEmit` clean.

With `flow.enabled=false` the recorder stores nothing and detection is unchanged; no existing test
was modified, skipped or weakened. The one test edit was giving the D-001 redirect assertion a 5s
budget, because the lazily imported route tree plus the Navigate effect needs longer than the 1s
default once the whole suite runs in parallel.

## Phase 2: persistence

New package `pk.ooad.ntd.persistence` (9 classes):

- `Database` opens SQLite in WAL mode with one writer and one reader connection and a
  `PRAGMA user_version` schema version. `FlowRepository` and `AlertRepository` own the two tables and
  use batched `INSERT OR REPLACE` inside one transaction per batch.
- `WriteBehindQueue` is bounded and drains on one daemon thread. `offer` never waits, so a full queue
  refuses the newest row and counts it; a sink that throws is counted, described once and survived.
  `flush` is a durability barrier: a batch taken off the queue counts as in flight until it is
  committed, so a caller that flushes and then reads sees the rows.
- `PersistenceService` implements `AlertListener`, subscribes the flow recorder's close listener, and
  runs a retention sweeper on its own schedule. A file that will not open degrades to `disabled`
  with one error in the event log rather than stopping the detector.
- `PersistenceSettings` and `PersistenceStatus` are records, so the API, the client and the tests
  read the same object. Every key takes an `ntd.` system property override.

API and client: `GET /api/flows/history` (newest first, 503 while the store is off) and
`GET /api/persistence/status` (Admin). The Flows page gained a Live and a Stored switch.

Tests added: `PersistenceTest` (6): disabled store refuses reads and imports, round trip with newest
first, retention sweep deleting only expired rows, a full queue refusing and counting, a throwing sink
survived, and closed flows reaching the store through the recorder listener.

## Phase 3: security hardening

- `pk.ooad.ntd.security.AuditLog`: a bounded ring of `Entry` records with an `Outcome` enum, separate
  denied and failed counters, and normalisation of nulls (a missing actor becomes anonymous, a missing
  outcome becomes allowed).
- The login rotates the session id on success and replaces the CSRF token with it
  (`auth.session.rotateOnLogin`). The session cookie is HttpOnly and SameSite=Lax, and
  `auth.session.secureCookie` adds Secure to it for a TLS deployment; the separate `csrf` cookie is
  SameSite=Strict. `LoginThrottle` answers 429 with a `Retry-After` header after five failures per
  username and address in five minutes.
- Every refused call is audited as it happens, along with login, logout, configuration reads,
  containment orders and releases and evidence exports. `GET /api/audit` is Admin only.

Tests added: `AuditLogTest` (5): disabled log, ring keeping the newest, separate counters, null
normalisation, blank actions and reset.

## Phase 4: offline Zeek import

New package `pk.ooad.ntd.zeek` (2 classes). `ZeekConnLogParser` reads the `#fields` header rather than
assuming a column order, converts each row into a `FlowRecord`, skips malformed rows and counts them,
and caps the import. `ZeekImportResult` records the counts, the hosts seen, the time span and the
problems. `Main --import-zeek <file>` builds the facade but never starts it, stores the flows through
`importFlows` and prints the summary plus every problem, or why the store is not available.

The importer is behind `zeek.enabled` (default true); with it off the command prints a note and
returns without touching the store.

The sample capture generated in phase 0 (1693 connections, `sample-conn.log` plus
`sample-conn.labels.csv`) is the file the demo imports.

Tests added: `ZeekConnLogParserTest` (5): header driven parsing, the sample file, malformed rows
counted and reported, the cap, and an empty file.

## Phase 5: threat intel

New package `pk.ooad.ntd.intel` (2 classes). `ThreatIntel` loads or parses a plain text feed of
`address-or-cidr label [severity]`, matches IPv4 only, counts the IPv6 and malformed lines it skipped,
and is quiet when the feed cannot be loaded. The shipped `threat-intel.txt` holds the RFC 5737
documentation ranges, so enabling the feature adds no alerts out of the box.

Tests added: `ThreatIntelTest` (6): parsing, comments and blanks, IPv6 and malformed lines counted, a
single address and a CIDR match, the fallback severity, and a missing feed staying empty.

## Phase 6: NDR detectors

Four detectors extend the existing `Detector` strategy and are built by the existing
`DetectorFactory.createNdr()`, so `createAll()` still returns the original four: `BeaconingDetector`
(steady rhythm with a jitter tolerance), `DataExfilDetector` (volume to an address outside the internal
prefixes), `LateralMovementDetector` (distinct hosts on management ports) and `ThreatIntelDetector`
(feed lookup). Each keeps a bounded per-source table and a fixed cooldown.

`DetectionEngine.setAdmission(Predicate)` is the other seam: an event refused by it is counted in
`getDroppedEvents()` and never reaches an observer or a detector. Containment uses it.

Tests added: `NdrDetectorsTest` (6): beaconing rhythm and cooldown, jitter rejection, exfiltration,
lateral movement naming the port, the feed bucket mapping, the four factory detectors silent by
default with `createAll()` still at four, and the admission seam dropping and counting an event.

## Phase 7: alert quality gate

`AlertGate` is a one method interface (`allow(Alert)`) with `ALLOW_ALL` as the default, so the engine
has a seam rather than a special case. `AlertQualityGate` folds repeats of the same (detector, type,
source, target) inside a window and applies a severity floor, counting both so the effect of turning
it on is measurable. It is installed with `DetectionEngine.setAlertGate` and evaluated before the
per-source cooldown is recorded, so a suppressed alert never silences the next genuine one.
`GET /api/alert-quality` reports the rule and the counters.

Tests added: `AlertQualityGateTest` (10): disabled gate, repeats inside the window, five distinct keys,
an out of order arrival, the severity floor, a null alert, the bounded key table, reset, the engine
seam proving a refused alert does not spend the cooldown, and a null gate restoring the default.

## Phase 8: flow anomaly model

New package `pk.ooad.ntd.ml` (5 classes), pure Java: `FlowFeatures` (six log-scaled values),
`FeatureVector`, `KMeans` (k-means++ with a fixed seed), `AnomalyModel` (per-dimension standardisation
and a score divided by the 95th percentile distance, clamped to 0..1) and `MlFlowScorer`.

The scorer learns from the same completed flows it scores, trains on its own thread, keeps the
previous model while a training pass runs, and reports `disabled`, `cold`, `training` or `ready` so a
model with no opinion never reads as a clean bill of health. Alerts land in `DATA_TRANSFER` because
the domain enum is a closed set of four; the detector name and the description carry the meaning.
`GET /api/ml/status` reports the state.

Tests added: `MlTest` (6): the feature vector, deterministic k-means, a disabled scorer staying
silent, cold then ready with an outlier scored and the per-source cooldown holding the second alert
back, the gate suppressing publication while the anomaly is still counted, and reset dropping the
model as well as the samples.

## Phase 9: cross-detector correlation

New package `pk.ooad.ntd.correlation` (1 class). `SiemCorrelator` implements `AlertListener` and
escalates a source that produces several distinct attack types inside one window, once per cooldown.
It ignores alerts whose detector name is its own, so a synchronous bus cannot make it feed itself, and
its source table is bounded. `GET /api/correlation/status` reports the rule and the counters.

Tests added: `SiemCorrelatorTest` (4): the escalation once the threshold is met, escalation suppressed
inside the cooldown, one type never escalating, and the correlator ignoring its own alerts.

## Phase 10: containment

New package `pk.ooad.ntd.containment` (1 class). `ContainmentService` records who asked for a block,
why, and when it lapses; `contain` clamps the duration, `release` is explicit, every action expires, and
the table is bounded. Enforcement is separate from record keeping: with `containment.enforce` off the
actions are visible but traffic keeps flowing, which lets an operator rehearse a response. With it on,
the service is installed as the engine's admission predicate, so a blocked source's events are dropped
before detection. `containment.auto` may block on a severe alert without an operator.

API: `GET /api/containment`, `POST /api/containment {ip, minutes, reason}`,
`POST /api/containment/release {ip}`. The two writes are Admin only, audited, and answer 409 while
the capability is off.

Tests added: `ContainmentServiceTest` (7): record keeping with enforcement off, admitting and dropping
with it on, expiry on a movable clock, the duration clamp, release, the bound, and automatic blocking
on a severe alert. `OperationsApiTest` covers the 409, the 404 on release and the viewer refusal.

## Phase 11: notifications

New package `pk.ooad.ntd.notify` (1 class). `NotificationService` keeps a bounded outbox of alerts at or
above a severity floor and, when a webhook URL is configured, posts each one as JSON from a small pool
with a per-call timeout. A webhook that fails, times out or is malformed is counted and described, and
the URL is parsed inside the guard so a bad value cannot escape into the detection path.
`GET /api/notifications` returns the outbox and whether a webhook is configured.

Tests added: `NotificationServiceTest` (7): the severity floor, the bounded outbox, a webhook delivered
to a local `HttpServer`, a failing webhook counted, a malformed URL contained, no URL meaning no call,
and reset.

is Admin only.
- Client: the Admin page gained one operations panel that reads every new status endpoint, orders and

  the reason shown instead of a zero that looks like a measurement.

Tests added: `EvidenceExporterTest` (6): the bundle layout, the manifest digests, the per-list caps,

`ComplianceServiceTest` (3) and the rest of `OperationsApiTest`.

## Phase 13: benchmarks

New package `pk.ooad.ntd.bench` (1 class). `Benchmarks.run(scale)` measures five operations with a
fixed operation count (event ingest, detection analysis, feature extraction, the quality gate and
k-means training), clamps the scale to at least 200, and reports microseconds per operation and
operations per second. A zero operation row reports zero instead of dividing by zero. `--benchmark
[events]` prints the table.

Tests added: `BenchmarksTest` (5): every measurement self describing, repeatable operation counts, the
tabular report, zero operations safe, and a tiny scale raised to the minimum.
